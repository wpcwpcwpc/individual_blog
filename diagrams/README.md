# diagrams —— 图表源

本目录是**全站图表的唯一真源**。站内页面、deck、PDF 都从同一批源文件产出，
不允许任何一处单独维护第二份副本。

## 约定

- 命名：`<语义前缀>-<主题>.mmd`
  - `arch-` 架构与结构
  - `flow-` 流程与管线
  - `seq-` 时序
  - `state-` 状态机
- 文件开头用 `%%` 注释写明用途与复用位置；`@desc` 行会作为 SVG 的无障碍描述：

  ```
  %% @desc 一句话说明这张图是什么
  %% 复用位置：项目页 / 文章 / deck
  flowchart LR
      A[节点] --> B[节点]
  ```

- 图一律为**对外重绘版**：不出现内部系统名、内网地址端口、真实文件路径、人员标识。
  脱敏扫描会把 `diagrams/` 纳入检查范围。

## 生成方式

```bash
npm run diagrams        # diagrams/*.mmd → src/assets/diagrams/*.svg
```

- 产物 SVG 是**生成物，禁止手改**（已加入 .gitignore，手改会在下次构建被覆盖）
- 渲染在 Node 中完成（jsdom + Mermaid），站点**不依赖客户端 Mermaid 运行时**
- 标签输出为 `<text>` 而非 `<foreignObject>`，保证 PDF、邮件客户端、各类预览器都能正确呈现

## 已知限制

Node 下没有真实布局引擎，文本宽度是按字符估算的（CJK 约 1em、拉丁约 0.56em）。
因此：

- 极端长标签可能仍有一点留白偏差，建议单节点标签保持简短（≤ 12 字）
- 标签里**不要用空格**做排版（Mermaid 会把它当换行点），需要分隔用中文标点或 `·`
- 复杂图（子图嵌套、大量交叉连线）建议先在本地 `npm run dev` 里过一眼再定稿
- **同排节点超过 4 个时，节点框可能轻微相接**：Mermaid 交给布局的宽度小于它实际绘制的框宽，
  且间距配置在部分图上不生效。长链路请拆成两行（用子图包一层并设 `direction LR`），
  或把节点精简到 4 个以内 —— 一张图讲一件事比塞满更好读
