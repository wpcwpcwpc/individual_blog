**🗣️ 大白话说这张图**：

1. **用户说话** → 进入 UI 层
2. **UI 层** 把消息交给 **QueryEngine（大脑）**
3. **QueryEngine** 开始循环：
   - 准备消息 → 调用 Claude API → 处理回复
   - 如果 Claude 说"我需要用工具"→ 执行工具 → 把结果告诉 Claude
   - 循环往复，直到 Claude 说"我回答完了"
4. **工具执行**时要经过权限系统和沙箱的检查
5. 最终结果返回给用户

### 每篇文档的结构（增强版）

核心 Agent 相关文档（02-06, 08-09, 14-15）已增强为以下结构：

```
📄 每篇增强文档包含：

1. 🎯 一句话理解
   └─ 用简单的类比建立第一印象

2. 🔮 直觉建设  
   └─ 生活化场景帮你理解"为什么需要"
   └─ 解决的核心问题是什么

3. 📋 技术内容
   └─ 原有的详细技术分析
   └─ 穿插"大白话说"降低理解门槛

4. 🎓 本章小结
   ├─ 核心要点（4-5 个关键点）
   ├─ 可迁移的设计原则（表格形式）
   ├─ 🧠 为什么这样设计？（设计决策深度分析）
   └─ 🤔 思考题（4-5 道，附提示）
```

### 每篇文档的阅读方式

1. **先看"一句话理解"** — 建立预期
2. **看"直觉建设"** — 获得"为什么"的直觉
3. **看架构图** — 理解全局结构
4. **读代码时看"大白话说"** — 降低理解门槛
5. **看"为什么这样设计"** — 理解设计决策
6. **做思考题** — 检验理解深度

### 四个学习层次

| 层次 | 目标 | 方法 |
|-----|------|------|
| **A. 理解** | 看懂代码在做什么 | 读文档 + 看注释 |
| **B. 修改** | 能做小改动 | 理解 + 做思考题 |
| **C. 推导** | 从零设计类似系统 | B + 理解"为什么" |
| **D. 迁移** | 应用到其他项目 | C + 提炼设计原则 |
