## ADDED Requirements

### Requirement: 镜像区落位与命名

搬运产物 SHALL 落在一个顶层独立目录 `mirror/` 之下，按来源项目 slug 分目录（`mirror/<slug>/`）。镜像区 SHALL 与站点源码目录（`src/`）、部署输入目录（`public/`）、内容资产目录（`diagrams/`、`deck/`）分离。

#### Scenario: 新增一个来源项目的镜像

- **WHEN** 需要搬运第二个来源项目
- **THEN** 在 `mirror/` 下新增一个 slug 目录，MUST NOT 与既有镜像目录混放

#### Scenario: 目录层级

- **WHEN** 一个来源项目本身含多个可独立展示的部分（如服务端与客户端）
- **THEN** 允许在该 slug 下再分层，层级 SHALL 在镜像区 README 中声明

### Requirement: 镜像区不参与构建

镜像区 SHALL NOT 进入任何构建输入或产物：MUST NOT 被站点构建（Astro）读取，MUST NOT 被拷贝至部署产物目录，MUST NOT 被站点页面或内容引用。

#### Scenario: 构建产物核对

- **WHEN** 执行一次完整构建
- **THEN** 构建输出中不含镜像区任何文件；镜像区缺失或损坏 MUST NOT 影响构建成功

#### Scenario: 内容层引用镜像

- **WHEN** 某页面或文章希望链接或内联镜像区代码
- **THEN** 该需求 SHALL 走另一个变更处理，MUST NOT 在本次范围内直接引用

#### Scenario: 阶段一不上站

- **WHEN** 阶段一完成
- **THEN** 线上站点不含任何镜像区内容；镜像区仅存在于仓库中

#### Scenario: 镜像区自身可运行与站点构建无关

- **WHEN** 镜像区按自身 README 启动后端与前端
- **THEN** 该过程 MUST NOT 依赖站点构建，站点构建也 MUST NOT 依赖镜像区；两者各自独立

### Requirement: 改造期不入库与揭幕

镜像区在改造期 SHALL 处于 gitignore 之下，使任何形式的暂存与提交都无法把未清理内容纳入版本历史。揭幕（解除忽略）SHALL 是单一显式动作，且仅在全量复核通过后执行。`mirror/README.md` SHALL 在本变更的批次台账中记录揭幕状态。

#### Scenario: 改造进行中提交代码

- **WHEN** 改造期执行一次 `git add -A` 与提交
- **THEN** 镜像区内容 MUST NOT 被纳入该提交

#### Scenario: 揭幕前置条件

- **WHEN** 准备解除忽略并提交镜像区
- **THEN** 全量脱敏扫描、体量核对、人工终审、本地验收均已通过，且结论可追溯

#### Scenario: 揭幕动作

- **WHEN** 执行揭幕
- **THEN** 移除 gitignore 中的镜像区条目，并在同一提交内完成镜像区入库

### Requirement: 排除清单

镜像区 MUST NOT 包含：本地配置文件与其备份（含真实凭证位）、构建产物、嵌入运行时、依赖安装目录、缓存目录、二进制与媒体文件、版本控制内部目录。排除规则 SHALL 在拷贝阶段即生效，并在搬运后以体量核对复查。

#### Scenario: 拷贝时遇到本地配置文件

- **WHEN** 源项目含被版本控制的本地配置文件或备份
- **THEN** 该文件 MUST NOT 进入镜像区；只允许提供值全为占位的示例配置

#### Scenario: 拷贝时遇到嵌入运行时

- **WHEN** 源目录含打包产物或内嵌的运行时目录（单目录即上千文件）
- **THEN** 该目录 MUST NOT 进入镜像区；体量核对以其存在为失格信号

#### Scenario: 缓存与依赖目录

- **WHEN** 源目录含缓存目录或依赖安装目录
- **THEN** 一律排除；镜像区只承载源码与必要配置模板

### Requirement: 可运行声明与边界

镜像区 SHALL 在根 README 中声明：经脱敏、可本地跑通、**不保证生产可用**、不依赖任何内部资源、不使用真实凭证。README SHALL 给出可执行的本地启动步骤，并明确验收已覆盖的范围与未覆盖的部分。

#### Scenario: 读者按步骤运行

- **WHEN** 读者按 README 步骤安装依赖并启动
- **THEN** 能启动后端与前端并走通已声明的验收项；未覆盖的部分在 README 中已注明

#### Scenario: 读者询问生产可用性

- **WHEN** 读者想把镜像区用于生产
- **THEN** README 已声明不保证生产可用（无部署、无并发与运维设计）

#### Scenario: 遗留断链

- **WHEN** 镜像区存在因删除造成的引用空洞
- **THEN** 该空洞要么随调用方一并 `CUT`，要么被判 `REPLACE` 并补齐；MUST NOT 保留影响启动的断裂

### Requirement: 来源一次性与零留痕

搬运 SHALL 为一次性动作：MUST NOT 使用子模块、远端引用或任何形式的持续同步。源仓库 MUST NOT 因本次搬运产生任何改动。源目录的真实路径 MUST NOT 出现在仓库任何文件（含注释、文档、脚本示例、提交信息）中。

#### Scenario: 仓库中的路径痕迹

- **WHEN** 审查镜像区文件头、README、变更文档与脚本
- **THEN** 不含源目录绝对路径、主机名或网络位置；来源信息仅以"一次性搬运、来源为内部仓库"这类泛化表述存在

#### Scenario: 源侧改动

- **WHEN** 搬运执行过程中
- **THEN** 源仓库工作树与提交历史均无新增改动

#### Scenario: 后续源变更

- **WHEN** 源项目继续演进
- **THEN** 镜像区默认不跟进；如需更新，SHALL 作为新的搬运批次处理，而非建立同步机制

### Requirement: 批次元数据登记

镜像区 SHALL 记录批次级别的元数据：批次序号、覆盖范围（泛化类别）、完成日期、复核结论。元数据 MUST NOT 含真实文件名、内部模块名或业务点定位。

#### Scenario: 记录一批完成

- **WHEN** 一批搬运与复核完成
- **THEN** 镜像区 README 或变更文档中新增一条泛化记录（批次序号、范围、日期、结论）

#### Scenario: 元数据泄露审查

- **WHEN** 审查批次记录
- **THEN** 记录内容与 `sanitization-gate` 的词表零命中，且无法从中反推内部目录结构
