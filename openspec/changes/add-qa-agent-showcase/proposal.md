## Why

简历对复杂系统的承载效率极低——一个多 Agent 编排平台、双向 MCP 桥接、评测体系、全链路可观测，在 A4 纸上只能写成两行字。需要一个公网落地点：面试官点开链接，**3 分钟内建立可信度**（这系统真跑起来了、规模是真的、我在其中的角色清晰），并留下**深挖钩子**（想看细节就有得看）。

同时有三个必须先解决的问题：

- **口径必须与代码一致**：同一件事在代码、内部文档、对外材料里有四个不同数字（注册数与目录数不等、旧文档数与代码不符），面试官真去数就会露馅。对外口径需先冻结为单一来源
- **这是在职项目，脱敏是红线**：内容全部重写、架构图全部重绘，不能出现内部系统名、内部域名、真实路径、精确内部指标
- **展示形态要分层**：3 分钟扫读与 30 分钟深挖是两种需求，单靠一种形态都满足不了

## What Changes

- **项目落地页 `/projects/qa-agent`**：五层架构总览图 + 关键数字（脱敏后）+ 我的角色与边界 + 演进脉络，作为简历链接的直接目标
- **概览 deck `/deck/qa-agent`**：约 12 页扫读版（问题 → 架构 → 各层要点 → 结果 → 联系），复用站点的图源与排版规范
- **深挖文章系列 `/posts/*`**（分期，先上 2 篇）：
  1. 用 spec-driven 流程管理一个多 Agent 系统的演化（差异化最强，头条）
  2. 为什么拆成多个专职 Agent 而不是一个大 Agent（编排与模型路由的取舍）
  3. 双向 MCP 桥接：懒加载客户端与反向暴露的取舍
  4. 三道闸门：Hook 管控、工具白名单、沙箱，防越权与幻觉
  5. 上下文工程：压缩、阈值、历史回填
  6. 让 LLM 给人打分：评测体系与 Judge 校准；以及指标口径统一
- **图表集（10 张左右，重绘）**：五层架构总览、Agent 编排、路由分发、MCP 双向桥、三道闸门、上下文四段、评测流水线、可观测分层、工程流程、一次运行的时序
- **内容侧脱敏**：扩充 `GLOSSARY.md`（内部系统/产品泛化映射、禁出词、指标区间化登记），维护 `SHOTS.md` 截图占位清单
- **PDF 兜底**：项目页内容的 PDF 导出，作为离线与附件场景的降级方案
- **简历接线**：简历一行链接指向 `/projects/qa-agent`，纸质版附二维码，PDF 作为邮件附件兜底

## Capabilities

### New Capabilities

- `showcase-content`: 内容架构与叙事规范——项目页结构、文章论点要求、口径单一来源、分层叙述（问题/架构/取舍/结果）、evergreen 表述
- `showcase-deck`: 概览 deck——页序结构、每页信息目标、与站点共用图源、移动端可读
- `showcase-sanitization`: 内容侧脱敏——泛化映射、禁出清单、指标区间化登记、图表重绘要求、发布前自检
- `showcase-resume-handoff`: 简历交付——稳定引用路径、二维码、PDF 兜底、联系渠道边界

### Modified Capabilities

- `sanitization-gate`（来自 `add-personal-site`）：禁出词表需在本变更中按项目实际内容扩充（内部系统名、产品名、指标项），并新增指标区间化登记；机制不变，仅词表与登记项变化

## Impact

- 依赖 `add-personal-site` 提供的地基（Astro 站点、排版规范、脱敏闸门、图表管线、部署链路）；本变更只新增内容资产与图源，MUST NOT 修改地基的机制实现
- 新增内容：`src/content/projects/qa-agent.md`、`src/content/posts/*.md`、`diagrams/*.mmd`、`public/pdf/*.pdf`、deck 静态产物
- 素材来源为雇主内部仓库（规格、变更记录、实现代码、内部文档），**仅经人工阅读与重写**，本仓库 MUST NOT 引用内部仓库路径或复制内部文档原文
- 雇主内部仓库 MUST NOT 新增任何本变更的文件（零留痕）
- 风险：口径不一致（数字打架）→ 由 `showcase-content` 的单一来源条款约束；脱敏漏网（NDA）→ 由地基的构建硬拦截 + 本变更的内容侧自检双闸门控制；内容量过大导致长期烂尾 → 分期策略，先上 2 篇即可交付可用链接
